Teepin Storage keeps your files in buckets inside a project. You reach them these ways, all showing the same buckets:

| Way in | For |
| --- | --- |
| **The console** | Browsing, uploading files and folders, previews and share links |
| **The SDKs** (Python, Node, Go) | Your applications: uploads of any size that resume after a crash, many files at once, verified downloads |
| **The REST API** | Buckets, listings, renames, deletes and share links, from any HTTP client |

## How files move

<Steps>
<Step>

### Encrypted on your device

The SDK or the console encrypts each file with its own key before any byte leaves your device.

</Step>
<Step>

### Signed by Teepin

Teepin's API reserves the upload and signs a request for exactly those bytes. The API only reserves, signs and records: it never receives your files.

</Step>
<Step>

### Sent straight to the storage network

Your device sends the encrypted bytes straight to the storage network. Teepin then checks that the network holds exactly what was signed, and records the object. Only then is the upload reported as saved.

</Step>
</Steps>

Downloads work the same way in reverse. Teepin checks access and signs the read, your device fetches the bytes from the storage network, and every byte is checked on your device before you get it.

Small files (up to 16 MiB) are packed together into one write. Larger files go in parts, sent in parallel. See [Large files](/docs/storage/large-files), and [Security](/docs/storage/security) for what is encrypted and what Teepin can see.

<Callout title="Uploads and downloads need an SDK or the console">
Files are encrypted and checked on your device, so plain HTTP clients such as curl can't upload or download file bytes. They can still manage buckets, list, rename and delete objects, and make share links.
</Callout>

## Concepts

- **Bucket.** A named container in a project. Names are 3 to 63 lowercase letters, digits, dots and hyphens, unique within the project.
- **Object.** A file in a bucket, addressed by its key, such as `photos/2026/beach.jpg`.
- **Folders.** Keys with `/` read as folders in the console and in listings with a delimiter. There is nothing else to create.
- **Versions.** Writing to an existing key replaces the object. The previous version is not kept.

Your files are stored encrypted on a decentralised storage network. The bucket and file names you choose stay in Teepin's own catalog: the network only ever sees random names and encrypted bytes.

## Your network

- Your device connects to `api.teepin.com` and to the storage network's host, which the API gives in each signed request. If your network only allows listed hosts, ask [support@teepin.com](mailto:support@teepin.com) for the storage network's current host.
- The storage network is reached over IPv4. On a network with IPv6 only, the network needs NAT64 and DNS64, which most mobile networks provide.

## The REST API at a glance

All routes are under `https://api.teepin.com/v1/storage` and need an API key with storage access.

| Method and path | Does |
| --- | --- |
| `POST /buckets`, `GET /buckets`, `GET /buckets/{bucket}`, `DELETE /buckets/{bucket}` | Create, list, read and delete buckets. A bucket must be empty to delete. |
| `GET /buckets/{bucket}/objects?prefix=&delimiter=&cursor=&limit=` | List, a page at a time. |
| `GET /buckets/{bucket}/object?key=` | An object's details: size, type, ETag, metadata. |
| `DELETE /buckets/{bucket}/object?key=`, `POST /buckets/{bucket}/objects/delete` | Delete one, or up to 1,000 at once. |
| `POST /buckets/{bucket}/object/rename` | Rename. Instant at any size. |
| `POST /buckets/{bucket}/object/link` | Make a share link. See [Share links](/docs/storage/share-links). |
| `GET /buckets/{bucket}/uploads`, `DELETE /buckets/{bucket}/uploads/{upload}` | List and cancel unfinished uploads in parts. |
| `GET /hold` | Whether your stored data is on hold for lack of credit. |

The routes that move files (reserving, signing and committing uploads, and signing reads) are meant for the SDKs, since each needs the encryption done on your device. Every route is described in the API's OpenAPI document at `https://api.teepin.com/v1/openapi.json`.
